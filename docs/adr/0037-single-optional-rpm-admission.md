# ADR-0037: 单一可选 RPM 准入限制

- 状态：Accepted
- 日期：2026-07-25
- 决策者：maintainer
- 取代：ADR-0008 中的辅助并发设计、ADR-0010/0011/0023 中的并发容量部分

## 背景

原实现同时提供每个上游凭据的 `max_concurrency`、生成请求队列，以及
`/v1/messages/count_tokens` 的全局/单凭据辅助并发上限。管理员必须协调多套限制：并发值偏低会让
实际 RPM 无法达到预期，RPM 再叠加并发又会产生第二个不可见瓶颈。多数上游公开的配额口径也是
RPM，而不是客户端可配置的在途请求数。

TPM（Tokens Per Minute）不进入本地限制。输出 Token 在请求前未知，Provider 对缓存、推理与
输入/输出 Token 的统计口径也不一致；增加 TPM 会重新形成与 RPM 互相制约的第二套准入限制。

## 决策

- `ProviderCredential` 与 `OAuthAccount` 各自保存可空的 `requests_per_minute`。`NULL` 表示不做
  本地 RPM 限制，交由上游 `429`、`Retry-After`、冷却和重试策略处理；非空值必须位于
  `1..=100_000`。
- 删除 `max_concurrency` 和辅助请求并发设置，不保留隐藏 Semaphore、固定连接数或其他本地并发
  上限。`/v1/messages/count_tokens` 与生成请求使用同一个账号 RPM。
- 每个稳定 `CredentialRuntimeHandle` 在内存中维护精确的滚动 60 秒请求时间窗。配置代际切换、
  Secret/Token 轮换不重置有限 RPM 的当前窗口；进程重启会清空。有限值改为另一个有限值时保留
  窗口并立即按新值判断；改为无限制时清空窗口，之后重新启用 RPM 时从空窗口开始。
- 调度按 Route + tier 的稳定轮询顺序尝试候选。选择候选和预留一个 RPM 名额是同一个运行时
  操作；锁只覆盖该凭据的窗口清理与预留，不跨网络 I/O。已预留的名额代表一次上游 Attempt，
  无论响应快慢、流式 Body 何时结束或 Transport 最终是否证明请求送达，都只在 60 秒后自然
  过期，不因请求完成而归还。自动重试的每次 Attempt 都重新消耗 RPM。
- `in_flight` 作为无上限的 RAII 生命周期计数保留，用于运行态观测、流式资源持有和停机诊断；
  它不参与准入、候选排序或 RPM 名额释放。Guard 在 EOF、错误、取消和 Drop 时仍只结算一次。
- 未建立会话绑定的请求在当前凭据 RPM 用尽时可以选择其他合格凭据；已建立绑定的请求只能使用原凭据，
  并通过统一有界 `QueueTicket` 等待其最早窗口到期、健康恢复、超时或取消。
- RPM 用尽返回精确的最早可用时间。等待循环同时监听统一 scheduler epoch、最早 RPM 到期时间
  和请求超时，避免既无唤醒又无界等待。固定凭据等待者对该凭据下一名额保持优先级，避免被
  普通轮询持续抢占。
- 本地拒绝使用 `local_rate_limit`，管理面显示 RPM 上限、滚动窗口已用/剩余、下一次释放时间、
  `in_flight` 观测值和等待者数量，不再显示最大并发、负载率或辅助容量。
- SQLite 只持久化管理员配置的可选 RPM。滚动窗口、`in_flight` 和等待状态均不持久化。

## 备选方案

- 同时保留 RPM 与并发：拒绝。两者会形成两个互相掣肘的用户配置瓶颈。
- 只保留并发：拒绝。它不能表达 Provider 通常公开的每分钟请求配额，长短请求还会产生完全不同
  的实际吞吐。
- 增加 TPM：拒绝。请求前无法准确知道输出 Token，且不同 Provider 的统计口径不统一。
- 使用固定分钟窗口：拒绝。分钟边界会允许瞬时双倍突发；滚动 60 秒窗口更直接地表达 RPM。
- 在 SQLite 中保存窗口：拒绝。RPM 是进程运行态，不需要跨重启恢复，也不应把数据面变成同步
  数据库写路径。

## 后果

管理面只有一套可选的账号级限速配置。未配置 RPM 时，本地不会为了一个隐含并发值阻止请求；
配置后则可以在发送上游 Attempt 前确定性地限制滚动 60 秒请求数。长流不会独占可配置容量，
但仍计入 `in_flight` 供管理员观察。

精确窗口需要为有限 RPM 的最近请求保存时间戳，内存使用量受每账号 `100_000` 的 Schema 上限
约束。RPM 名额是请求速率事实而不是可归还资源，因此本地准备阶段后续失败会采取保守计数；这
避免复杂的回滚协议和并发超发。

## 验证

- Domain/SQLite 测试覆盖空值、上下界、创建更新、重启加载与从历史 migration 前向升级。
- Runtime 测试覆盖并发预留绝不超过滚动窗口、60 秒到期、动态升降/关闭限制、热更新不重置窗口、
  多凭据轮询、固定等待优先、无丢失唤醒及每次重试单独计数。
- 流式测试继续覆盖 `in_flight` 在 EOF、错误、取消和 Drop 时只释放一次，但验证流结束不会归还
  RPM 名额。
- 管理 HTTP 与 Web 测试覆盖可选 RPM 的创建、编辑、展示、恢复无限制，以及负载均衡运行态 DTO。
