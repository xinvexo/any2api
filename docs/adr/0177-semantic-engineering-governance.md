# ADR-0177: 语义工程治理

- 状态：Accepted
- 日期：2026-08-22
- 当前事实：[架构地图：验证与治理](../../ARCHITECTURE.md#9-验证与治理)
- 替代：[ADR-0170](0170-current-decision-register.md) 的文档维护方式
- 被替代：无

## 背景

把所有当前事实放进一个大型规范，并用源文件形状、精确导出文本和固定实现数量阻断 CI，曾帮助早期仓库快速
统一形式。随着实现增长，这些规则开始制造包装模块、重复文档和等价重构失败，却不能证明协议、配置或安全语义。

## 决策

ARCHITECTURE 只做系统地图和跨主题不变量；少量主题文档各自拥有当前事实；ADR 按独立决策创建并保持历史语境。
代码 Registry、Migration 和生成契约拥有机器可枚举事实，不在文档复制。

自动门禁只保留可可靠判断的语义：Workspace 依赖方向、Migration 历史和官方客户端 baseline 安全。文件大小、
模块内聚、公开出口清晰度和测试重复由编译器、测试和评审结合判断，不把某个数字或源码字符串当成架构证明。

## 备选方案

- 继续维护单一大型规范：入口唯一，但主题耦合和同步成本持续上升。
- 为每次修复创建 ADR：把完成日志误当长期决策历史。
- 对文件行数和源码文本设置硬失败：易执行，但会奖励机械拆分并惩罚等价重构。
- 完全删除架构检查：会失去 Migration 和依赖方向等高价值自动保证。

## 后果

文档读取和变更范围缩小，代码组织可以围绕内聚性演进。代价是评审者需要对职责和复杂度作判断，无法依赖单个
数字。主题之间必须用链接而不是复制事实，Accepted ADR 的变化要通过后继记录表达。

## 验证

链接检查、陈旧术语搜索、`cargo xtask architecture-check`、相关契约测试，以及周期性人工审查文档与代码所有权。
