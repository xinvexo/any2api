# ADR-0055: 系统总览采用扁平布局和 RequestLog 调用分析

- 状态：Accepted
- 日期：2026-07-28
- 修订：2026-08-03
- 决策者：maintainer
- 调整：ADR-0039 的系统总览展示

## 背景

现有系统总览位于应用主 Surface 内部，却又把服务状态、请求调度和会话绑定分别放进大卡片，
Provider 汇总再放进小卡片，形成“大框套小框”。页面只展示当前进程运行态，无法回答日志保留期内
实际消耗了多少 Token、某个时间段调用是否增长、哪些模型被调用最多。

RequestLog 已持久化最终请求的公开模型、状态与协议解析出的输入/输出 Token。新增永久计数表或第二套
采集服务会重复现有真相来源，也会让日志清理后总览口径与请求日志不一致。

## 决策

- 总览在现有应用主 Surface 内使用扁平 section、指标带、列表和细分隔线，不再为每个模块创建大卡片，
  Provider 汇总也不使用嵌套小卡片。
- 新增只读 `GET /api/admin/overview/usage`，固定支持 `range=1h|24h|7d|30d`，默认 `24h`：
  - `1h`：12 个 5 分钟桶；
  - `24h`：24 个 1 小时桶；
  - `7d`：28 个 6 小时桶；
  - `30d`：30 个 1 天桶。
- 响应返回生成时间、日志保留窗口累计、所选时间段累计、按时间升序的完整时间桶，以及所选范围内
  按 `public_model` 排序的前 12 项。其余模型合并为“其他”；`public_model IS NULL` 单独表示
  “未识别模型”，不能与“其他”合并身份。
- 请求只按最终 RequestLog 计算一次，2xx 为成功，其余为失败；RequestAttempt 不进入图表。
- Token 总量固定为 `input_tokens + output_tokens`。缓存读写 Token 是输入明细，不重复相加；缺失 Token
  字段按零参与求和，同时返回至少一个 Token 字段存在的请求数，供 Web 显示 usage 覆盖度。
- Token 累计通过十进制字符串传输，避免 JSON 进入 JavaScript 后超过安全整数；Storage 使用受校验的
  非负整数聚合，异常或溢出使本次统计查询失败，不能返回截断值。
- Web 用 URL 查询参数保存时间范围。请求数、总 Token、usage 覆盖数和平均 RPM
  全部取所选范围并随范围切换；平均 RPM 固定以该范围的完整分钟数为分母，不按活跃分钟放大结果。
  输入/输出 Token 不作为首页独立指标。宽屏左侧使用低饱和的 monotone 平滑时间曲线显示调用量并明确标出
  失败调用，右侧使用约 170px 的紧凑饼图显示模型占比；窄屏上下排列。饼图最多展示八个扇区，
  按调用量取前七项，并把剩余 API 模型项在纯展示层守恒合并为“其余 N 个模型”；如果管理 API
  已经包含无法得知真实模型数的“其他”聚合，则使用“其余模型”，不能伪造数量。两图同时展示。
  图表直接使用 `chart.js` 的按需注册模块实现曲线、坐标、面积、悬浮提示和饼图扇区，不引入额外
  React 包装层。Chart.js 进入 Overview 页面内部第二级懒加载的图表子分块：路由分块先渲染服务状态、
  查询状态和统计指标，只有有效统计数据开始展示图表区域时才请求图表实现；加载期间使用与最终双图
  网格和高度一致的可访问骨架，不能让页面主体继续被 Chart.js 的解析执行阻塞。此前评估的
  `frappe-charts` 在离散非负计数上会产生低于零点的 spline 过冲，窄屏横轴标签也无法保持可读，
  因此不作为实现。2026-08-03 的同一生产构建中，拆分前 Overview 路由分块为 205.05KB 原始体积、
  71.06KB gzip；拆分后路由分块为 18.02KB / 5.74KB，独立 `OverviewCharts` 分块为
  187.74KB / 65.33KB，HTML 入口不 modulepreload 图表分块。图表分块仍明显小于此前 Recharts 方案
  约 117.8KB gzip；可访问文本摘要、URL 范围和紧凑响应式布局仍由本 feature 负责。
- Overview 的自动查询每 60 秒产生新统计数据时，现存 Chart.js 实例只替换数据与配置并调用
  `chart.update("none")`，不得销毁实例或重放入场动画；主题 Token 变化仍销毁并按最新数据重建实例，
  以确保 Canvas 内已解析的颜色全部刷新。组件卸载必须断开主题观察并只销毁当前实例一次。
- 历史统计来自 SQLite 保留窗口，不持久化额外累计、不参与启动恢复、路由、RPM、健康、额度或计费。
  日志关闭后已经保留的记录仍可查询；被保留策略清理的记录同步从总览累计中消失。

## 后果

首页可以展示所选时间段内真实记录到的 Token 总量、平均 RPM 和调用趋势，并明确缺失 usage 的覆盖边界。页面减少视觉容器层级，
但仍保留 ADR-0039 要求的固定规模运行态聚合。统计查询会增加只读 SQLite 聚合负载；固定范围、
`started_at_ms` 索引、最多 30 个时间桶和最多 13 个模型聚合输入行把管理响应保持有界。

## 验证

- Storage 测试覆盖保留窗口/所选范围累计、Token 口径、空时间桶、成功失败、未识别模型和前 12 项加
  “其他”的守恒关系。
- 管理 HTTP 契约测试覆盖默认/显式范围、无效范围、十进制 Token 字符串与 `Cache-Control: no-store`。
- React 契约测试覆盖安全整数校验、Token 字符串与时间桶连续性；组件测试覆盖 URL 范围、随范围更新的
  请求/Token/平均 RPM、同时展示的时间曲线与模型饼图、空数据、usage 覆盖提示和无嵌套 Surface。
- 生产构建记录 Overview 路由分块与图表子分块的原始/gzip 体积，并检查 HTML 入口不预载图表分块；
  组件测试固定双图加载骨架的两列结构与高度。
- 图表生命周期测试覆盖数据刷新复用实例并使用无动画更新、主题变化按最新配置重建，以及卸载清理。
- 前端在桌面与 390px 视口下保持无水平溢出，图表提供可访问文本摘要和非颜色唯一信息。
