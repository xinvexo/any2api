# ADR-0171: 单节点模块化单体

- 状态：Accepted
- 日期：2026-08-22
- 当前事实：[架构地图](../../ARCHITECTURE.md#3-workspace-模块)
- 替代：[ADR-0170](0170-current-decision-register.md) 的产品与模块部分
- 被替代：无

## 背景

any2api 服务一个管理员控制的自托管实例。请求调度、配置和凭据都需要低延迟共享状态，但产品没有租户隔离、
独立扩缩容或跨节点一致性需求。

## 决策

采用一个进程、一个 SQLite 数据目录和一个可执行文件的模块化单体。Workspace crate 用于隔离领域、协议、
Provider、网络、编排、存储、HTTP 和少量 unsafe/性能边界；`app/any2api` 是唯一 Composition Root。

边界以依赖方向和职责为准，不以 crate、文件或目录数量作为目标。可以在不反转依赖的前提下合并无独立职责的
薄层。

## 备选方案

- 微服务、Redis、PostgreSQL、消息队列：增加部署与一致性成本，却没有单节点产品收益。
- 一个没有内部边界的大 crate：文件更少，但 Provider、协议、网络与 SQL 更容易相互渗透。
- 为每个 Provider 建立独立服务：复制调度、健康、OAuth 和日志，且不能改善个人实例扩展性。

## 后果

部署、事务和运行态协调保持简单；编译期依赖边界仍能防止多数跨层耦合。代价是单进程故障域和垂直扩展上限，
这与产品范围一致。未来只有真实的独立扩缩容或隔离需求才能 supersede 本决定。

## 验证

Cargo metadata 依赖边界检查、Registry 契约测试、单实例锁和完整应用集成测试。
