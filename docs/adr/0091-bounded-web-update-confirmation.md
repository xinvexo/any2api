# ADR-0091：Web 自更新确认的有界恢复状态

- 状态：Accepted
- 日期：2026-08-03
- 决策人：项目维护者
- 修订：ADR-0065

## 背景

管理员接受更新后，Web 以全屏遮罩阻止继续修改配置，并同时轮询受保护的更新状态和公共健康版本。旧状态机
只有目标版本健康、服务端 `failed`、或连续三次 `idle` 三个出口。两个请求都失败时会无限重试；tab 刷新又从
`sessionStorage` 恢复同一 pending 目标，因此二进制无法启动或服务长期不可达会永久把该管理页面设为 inert。

用固定短超时直接宣布“更新失败”也不正确。旧进程在收到 restart 后先停止 accept，再按设置执行请求 drain、
后台任务、遥测、SQLite 和 runtime 收尾；合法停机预算可以超过一分钟。网络抖动、管理员会话因重启失效、
以及仍在退出的旧版本健康响应都不能证明安装失败。ADR-0089 的自动二进制回滚会让旧版本重新提供健康响应，
但其管理状态内存已经重置，浏览器仍必须区分“明确无任务”和“因会话失效读不到状态”。

## 决策

1. 成功条件保持唯一：无缓存 `/api/health` 返回的 `application_version` 与本次精确目标版本相等。旧版、其他
   版本、单次网络成功或更新状态 `restarting` 都不是成功。
2. 明确失败条件只有两类：服务端返回 `phase=failed`；或可连续三次读取到 `phase=idle` 而目标健康仍未出现。
   前者显示稳定失败码文案，后者说明任务已中止/进程已回到无更新运行态；两者允许“重新尝试”再次提交安装。
3. 每次成功读取 `checking/downloading/installing/restarting` 都是权威活动观测，并重置不可确认截止时间。状态
   请求拒绝、超时或返回非法响应时开始累计；期间任何新的活动状态都会清零。健康请求独立运行，目标版本在
   任意时刻出现都优先成功。
4. 连续 90 秒没有权威活动状态且没有目标健康响应时，不猜测服务端任务结果，进入独立
   `unconfirmed` 状态。文案明确“更新可能仍在进行”；若能读取到非目标健康版本，可以作为当前观测版本展示，
   但不能据此宣称失败。
5. `unconfirmed` 清除本 tab 的 pending target，停止 `beforeunload`，在 portal 遮罩上提供“继续等待”和
   “返回”。继续等待重新保存目标并从 90 秒新窗口恢复状态/健康轮询，不调用 install；返回解开 root inert、
   释放共享引用计数 body scroll lock 并移除遮罩，后台更新不受影响。该锁与移动导航、Drawer、Dialog 共用，
   只有最后一个遮罩退出时才恢复首个锁定前的 body 样式。用户在该状态刷新也因 pending 已清除而回到普通管理页。
6. 明确失败同样清除 pending；其“重新尝试”仍调用 install。running 阶段继续不可取消，防止一个短网络抖动
   直接放开控制面；本决策不增加服务端取消、更新任务持久化或浏览器凭据存储。

## 后果

- 永久不可达不再造成永久 tab 锁死，合法长停机也不会被前端伪造为确定安装失败。
- 默认最坏停机接近或超过 90 秒时，用户可能先看到“无法确认”；继续等待是无副作用操作，目标版本稍后出现
  仍会正常完成。
- 回滚旧版本且状态端点可读时会快速通过连续 idle 进入明确失败；会话失效使状态不可读时，最多 90 秒进入
  无法确认，由用户选择继续观察或返回。

## 验证

- 组件测试使用虚拟时间让状态与健康持续拒绝，证明 90 秒前仍锁定、到期后显示“继续等待/返回”、清除
  sessionStorage 和 beforeunload；继续等待不增加 install 请求，并重新进入锁定轮询。
- 测试覆盖一次/间歇网络失败被活动状态重置，不提前解锁；连续 idle 仍走明确失败；非目标健康永不触发完成。
- 既有目标版本健康测试继续覆盖完成、短暂展示与自动刷新。
