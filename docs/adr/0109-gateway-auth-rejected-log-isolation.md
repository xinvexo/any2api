# ADR-0109：Gateway 鉴权拒绝日志的低优先级容量隔离

- 状态：Accepted
- 日期：2026-08-04
- 决策人：项目维护者
- 修订：ADR-0015、ADR-0051、ADR-0092

## 背景

全局 HTTP 访问日志位于公开 Gateway 鉴权层之外，所以缺少、冲突或无效 Gateway Key 的 `/v1`
请求也会完整进入审计。该覆盖是必要的，但现有 SQLite 容量只按全表最旧顺序淘汰；容量已经满时，一条
成本很低的未认证请求就能删除一条更早的正常代理或管理审计记录。相同流量还可以占满共享的非阻塞遥测
队列，使随后完成的正常 RequestLog 或 HttpAccessLog 无法入队。

不能用最终 HTTP 状态码推断该类别：已成功通过 Gateway 鉴权的请求可能收到上游 `401`，这类记录包含真实
路由故障，必须保留正常优先级。按源 IP 限流会受到可信代理配置、NAT 和地址轮换影响，并改变公开 API 的
请求处理语义；采样则直接丢失单次鉴权探测。两者都不是当前问题的最短正确路径。

## 决策

1. Gateway 鉴权中间件对所有在建立 `AuthenticatedGatewayApiKey` 之前返回的拒绝响应附加仅进程内可见的
   `GatewayAuthRejected` Response Extension。HTTP 访问日志中间件消费并移除该标记，把
   `gateway_auth_rejected` 写入领域记录和 SQLite。客户端不能通过 Header 或 Body 设置该值，标记也不进入
   对外响应。已鉴权请求的本地或上游 `401` 保持 `false`。
2. 继续让每个 `/v1` 请求经过相同的捕获、保留判断和非阻塞遥测提交；不增加源 IP 限流或采样，也不新建
   第二套 Writer、数据库或失去全局顺序的旁路。现有有界队列满载时允许丢弃并计数的契约保持不变。
3. `gateway_auth_rejected` 数据事件的子容量按每请求捕获的 `logs.telemetry_queue_capacity` 四分之一向下取整，
   总容量小于四时使用一个槽的下限。该子计数与总 queue slot 原子预留；拒绝或发送失败必须回滚，Writer
   接收、正常停机和 abort 必须精确释放。其余槽可由 RequestLog、已鉴权/管理 HttpAccessLog 和 Gateway
   使用记录占用。
4. SQLite 前向 Migration `0011` 增加非空布尔列和
   `(gateway_auth_rejected, started_at_ms, request_id, exchange_bytes)` 覆盖索引。旧记录没有可靠证据证明当时
   是否在鉴权前失败，统一回填 `false`，禁止根据状态码猜测或改写既有历史。
5. 鉴权拒绝记录的行数与交换字节子容量分别按 HttpAccessLog 全局预算的四分之一向下取整，极小预算使用一
   的下限。
   每次批量写入和周期清理先从最旧鉴权拒绝记录中释放以下两类压力的较大者：该类别自身超出四分之一，或
   全表超出总预算。随后才对仍然存在的全表超额执行原有最旧优先裁剪。因此从一个已经满足全局容量的状态
   追加任意数量的鉴权拒绝记录，只会淘汰该类别记录；正常历史仍可使用全部空闲预算，并能优先挤出拒绝
   记录。正常历史自身超过总预算时仍按全局最旧顺序收敛。
6. 四分之一是集中定义的同一容量份额，不新增两个只服务这一类别的 Setting。默认预算下最多保留 50,000
   行、64 MiB 原始交换，并为队列中其他遥测保留至少四分之三；管理员仍可通过现有总行数、总字节和队列
   设置调整实例规模。公开遥测指标继续报告整体 queued/in-flight/dropped/persisted，不增加高基数维度。

## 后果

- 廉价的 Gateway 鉴权探测仍然可审计，但不能独占正常历史的持久化预算或默认队列容量。
- 分类来自真实鉴权控制流，不会把 Provider/API Key 故障返回的 `401` 错当成低优先级噪音。
- 保持单 Writer、单事务和清理命令的既有顺序，不引入按 IP 状态表、采样解释或第二数据库。
- 有界队列和有限持久化仍不承诺无限流量下零丢失；超出拒绝类别子容量的记录按既有 dropped 指标或最旧
  类别淘汰显式结算，而不是牺牲正常审计历史。

## 验证

- Server/HTTP 契约证明缺失或无效 Gateway Key 被标记，而成功鉴权后产生的状态不依赖 `401` 推断。
- Runtime 测试在阻塞 Writer 时证明鉴权拒绝事件只能占队列子容量，剩余槽仍接受正常记录，所有计数最终
  守恒。
- Migration 升级测试证明代表性旧记录保留并回填 `false`，新覆盖索引列顺序固定。
- Storage 测试分别用行数与交换字节压力证明鉴权拒绝洪泛不会删除正常历史，并继续覆盖全局容量收敛。
