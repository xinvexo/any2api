# ADR-0173: RPM 准入、粘性与流式提交边界

- 状态：Accepted
- 日期：2026-08-22
- 当前事实：[路由、重试与流式生命周期](../architecture/routing-and-streaming.md)
- 替代：[ADR-0170](0170-current-decision-register.md) 的调度与流式部分
- 被替代：无

## 背景

Provider API Key 和 OAuthAccount 需要共享调度，但具有独立持久化生命周期。流式响应又引入一个不可逆时刻：
客户端收到首字节后，任何换路都会造成两条上游响应拼接或状态伪造。

## 决策

两类凭据编译为统一 `RoutingCredential`。本地 RPM 是面向管理员的准入限制，选择与 reservation 原子完成；
`in_flight` 仅表示资源生命周期。显式会话绑定完整候选，配置 generation 决定绑定是否仍有效。

重试只在下游未提交、错误提供足够 `RetrySafety` 且预算允许时发生。提交任何响应字节后固定当前 Attempt，禁止
换候选、拼接流或补造成功终止。Runtime 队列、窗口、绑定、健康和事件不跨进程恢复。

## 备选方案

- 同时提供 TPM、并发和权重等多套准入：个人实例难以理解，也产生相互冲突的等待语义。
- 提交后透明续接另一上游：无法保证 token、工具调用和 usage 的一致性。
- 持久化队列与会话：把进程重启升级成请求恢复协议，超出产品容灾边界。
- 仅按 Provider 绑定：无法固定实际凭据、模型、代理和协议目标。

## 后果

准入和失败语义可预测，逻辑 Request 与 Attempt 可以准确分层统计。代价是部分提交后的流式故障必须直接暴露，
不能以另一账号“修复”；进程重启也会失去会话粘性。

## 验证

RPM 窗口与唤醒测试、generation 热更新测试、粘性并发测试、RetrySafety 矩阵、SSE 任意切分和提交前后契约。
