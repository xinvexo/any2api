# ADR-0178: 基于证据的 OAuth 本地额度估计

- 状态：Accepted
- 日期：2026-08-22
- 当前事实：[存储、配置与安全：OAuth 目录和额度快照](../architecture/storage-and-security.md#oauth-目录和额度快照)
- 替代：[ADR-0170](0170-current-decision-register.md) 的额度估计部分
- 被替代：无

## 背景

部分 Provider 只返回额度窗口使用百分比，而管理员希望看到本机请求对应的成本和近似容量。相邻刷新之间的
百分比变化会受到上游量化、异步记账和漏刷影响；窗口耗尽后购买 Credits 又可能接管请求，继续累加会把两种
资源混为一个 included-window。

## 决策

只有 Provider 给出明确成本单位时才估计。估计使用官方周期起止和刷新 observation fence，直接汇总该账号在
周期内已持久化的 RequestLog 成本。官方使用率达到最低可信门槛后才用“本地已用 / 官方百分比”外推容量。

当官方窗口耗尽且可用 Credits 接管时，included-window 估计冻结在最后可信容量；没有可信容量时冻结接管
fence 前的正数本地总和。后续 Credits 消耗不再改变该值。估计身份优先使用 Provider 导出的稳定主体，缺失时
回落到账号和 token generation；订阅身份变化使旧容量失去外推资格。

成本先按实际目标模型选择费率。请求只能表达 Fast 意图，只有上游最终响应确认的 effective speed tier 才使用
Fast 费率，否则按标准档。升级无法可靠迁移旧估计身份或接管边界时，保留官方观测并让派生状态冷启动。

## 备选方案

- 用相邻官方百分比和本地增量反推：小分母、漏刷和异步记账会放大误差。
- 继续累计耗尽后的整周期成本：把 included-window 与购买 Credits 混合。
- 根据余额差或请求时间猜逐请求扣款来源：Provider 没有提供可审计证据。
- EMA、限幅或异常值删除：输出更平滑，但会隐藏真实证据不足。
- 每次 token/代理变化重置：把同一稳定上游主体误认为新容量。

## 后果

周期记录完整时，本地 used 随持久化事实单调增长，进程重启或漏刷不会创建新的小样本；Credits 接管后显示值
保持可解释。代价是数据保留不完整、身份证据变化或使用率过低时容量保持未知，系统不会用猜测填满 UI。

## 验证

周期边界与 observation fence 测试、最低使用率测试、Credits 接管冻结、稳定身份/订阅变化、费率与最终 speed
tier、Migration 冷启动和 RequestLog 成本查询测试。
