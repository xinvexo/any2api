# ADR-0162：日志使用 SSE 通知与游标连续流

- 状态：Accepted
- 日期：2026-08-17
- 决策者：maintainer
- 修订：ADR-0069、ADR-0107、ADR-0159、ADR-0163（统一实时事件入口）；2026-08-17
  取消系统日志自动刷新偏好并收敛日志交互

## 背景

请求日志和系统日志已经具备提交后 SSE 失效通知与带头部锚点的 Keyset Cursor，但管理 Web 仍按
`page + page_size + total` 呈现传统后台分页。任意跳页要求 SQLite 执行精确 `COUNT(*)` 和排序键
`OFFSET` 边界定位；日志持续写入时，页码也不能表达“跟随最新”与“正在浏览历史”这两种不同状态。

日志管理的主要工作流是持续观察最新记录、顺序回看历史和按需查看单条详情。它不需要随机页码，SSE
也不应成为第二份日志正文数据面。浏览器还必须在长时间打开时保持内存与 DOM 有界，不能因为实时更新
持续累积所有摘要或缓存多条原始 HTTP 交换正文。

## 决策

- `GET /api/admin/request-logs` 与 `GET /api/admin/system-logs` 固定读取最近 3 天，每批最多 100 条。
  首次读取不带 `cursor`；响应返回 `items`、可选 `next_cursor`、`has_more` 和既有附加元数据，不再
  返回 `page`、`page_size`、`total` 或当前 Cursor，也不接受页码与页大小参数。
- Cursor 是版本化、不透明且按日志类型和筛选作用域隔离的值。它只编码首次读取时最新可见行的
  `(started_at_ms, request_id)` 头部锚点、下一批的排他边界，以及 RequestLog 结构化筛选指纹或
  HttpAccessLog 的 `show_admin_operations` 状态。筛选作用域不匹配和畸形 Cursor 继续返回
  `invalid_request`；旧 Cursor 不做兼容。
- Storage 始终按 `(started_at_ms DESC, request_id DESC)` 查询同一筛选集合，并最多读取 `limit + 1`
  条摘要来生成下一 Cursor。禁止为列表执行 `COUNT(*)`、OFFSET 跳页或读取详情 BLOB；SQLite Schema
  与现有排序索引不变。损坏 RequestLog 行仍按原始排序键推进边界并逐行隔离。
- `/api/admin/events` 仍只推送当前内存 epoch，并与 `overview_snapshot` 共用连接；不携带日志正文、详情、Secret 或 Cursor。浏览器原生
  重连后由连接初始 epoch 触发 HTTP 追赶：从无 Cursor 的最新锚点开始，沿 `next_cursor` 连续读取，直到
  与当前已知持久化 Request ID 重叠、没有更早数据或达到 3000 条缓存边界。浏览器把连续变更事件在
  约 100 ms 内合并，且同步单飞执行，避免每个事件触发一次查询或并发结果乱序。
- RequestLog 的 `active_items` 只随不带 Cursor 的最新批次返回，最多 100 条且不占用持久化批次大小。
  Web 以 Request ID 合并活动与最终摘要；最终记录可见时同一活动项必须被替换，不能同时出现。
- Web 使用 TanStack Infinite Query 顺序读取更早 Cursor。桌面使用固定表头、固定行高的 TanStack
  Virtual 表格；移动端使用紧凑连续卡片并保持同一加载与缓存模型。接近历史末端时自动读取下一批，
  不展示页码、每页条数或分页器。
- 浏览器最多保留 3000 条日志摘要。跟随最新时，新批次从头部合并并从旧端裁剪；浏览历史并加载更早
  批次时，从新端裁剪。任何裁剪和前插都必须按固定行高补偿滚动位置，保持当前可见记录不跳动。
- “位于最新”由日志滚动区的顶部阈值判定。位于最新时 SSE 结果立即合并并维持顶部；用户离开顶部后，
  不把新摘要写入当前链，也不长期保存第二份 pending 批次，只在内部记录需要追赶。页面不显示居中的
  “有 N 条新日志”提示；离开最新位置时提供固定在右下角且不参与布局的“回到顶部”按钮。选择该按钮时
  重新执行有界 HTTP 追赶，以得到的连续新 Cursor 链替换旧链并回到顶部；手动刷新只读取一个最新批次
  并重置链。筛选、`show_admin_operations` 切换和系统日志清理成功同样重置链。
- 请求日志和系统日志仅在双击整行/整卡片时打开右侧 Drawer；键盘聚焦行后仍可使用 Enter 或 Space，
  单击只用于选择和复制文本。窄屏使用同一组件的 Sheet 布局。详情按 Request ID 懒加载，关闭后只允许
  短期 Query 缓存回收，不建立长期详情列表缓存。请求日志独立 deep link 仍可用。
- 两类日志只对真正从最新端前插的新摘要播放一次短入场过渡；Cursor 加载并追加的历史摘要不得播放入场
  动画。活动请求使用克制的背景呼吸提示仍在执行，同一 Request ID 从活动项转为最终项时播放一次结算
  过渡；系统减少动态效果设置时全部禁用。
- 系统日志保留手动刷新、“显示管理操作”和有序清理；页面挂载且已认证时始终订阅统一 SSE，不提供自动
  刷新开关或对应浏览器偏好。清理成功必须取消旧详情、清空列表与内部待追赶状态，再从无 Cursor 的最新
  读取开始。
- 管理前端的日志 URL 从共享 `ADMIN_API_PREFIX = "/api/admin"` 构造；公共 `/v1/*` 与 `/api/health`
  不属于该前缀，也不随本决策改变。

## 备选方案

- SSE 直接推送完整日志：会复制 SQLite 真相、扩大 Secret/正文泄漏面，并需要回放、顺序和断线恢复协议，
  因此不采用。
- 保留页码并只给当前页加实时刷新：无法自然表达连续流，仍保留 COUNT、跳页与写入期间的视图漂移，
  因此不采用。
- 浏览器无限累积所有历史：长时管理会话的内存和虚拟列表索引仍会无界增长，因此不采用。

## 后果

最新观察、历史浏览和断线恢复成为三种明确状态；没有日志变化时不轮询，有突发写入时也不会逐事件查询。
列表读取只做索引驱动的有界 Keyset 查询，越深历史不会增加单次查询成本。代价是取消随机跳页和精确总数，
浏览器返回最新时会丢弃当前历史游标链；这与实时日志工作流一致。

## 验证

- Storage 测试覆盖头部插入后历史 Cursor 稳定、相同时间戳按 Request ID 排序、删除边界、筛选作用域和
  损坏行跨越，且查询路径不再需要页码、COUNT 或 OFFSET。
- Server 测试覆盖两类 Cursor 隔离、筛选不匹配拒绝、固定批量、`next_cursor`/`has_more` 契约与活动/
  最终去重。
- Web 测试覆盖 SSE 合并、重连同步、Infinite Query 继续加载、3000 条裁剪、历史位置不改写可见链、
  右下角回到顶部、筛选/清理重置、活动转最终去重、双击打开 Drawer、短期详情缓存，以及新摘要入场/
  活动呼吸/结算过渡不会在加载历史 Cursor 时误触发。
- 使用桌面与移动视口验证固定表头、行高、滚动锚点、卡片文本截断、Drawer/Sheet 和无重叠；运行 Rust
  fmt/clippy/test、Web typecheck/lint/test、`build:embedded` 与 `check:embedded`。
