# ADR-0107：日志使用带头部锚点的 Keyset 与按页定位

- 状态：Superseded by ADR-0162
- 日期：2026-08-04
- 决策者：maintainer
- 修订：ADR-0015、ADR-0051；2026-08-16 补充 HttpAccessLog 管理活动筛选作用域；2026-08-17 由 ADR-0162 取代页码与随机定位语义

## 背景

RequestLog 与 HttpAccessLog 原先使用 `page + page_size + OFFSET`。单次响应中的 `COUNT` 和当前页位于
同一 SQLite 读事务，因此该响应内部一致；但浏览跨越多个请求。用户读取第一页后，只要 Writer 在头部插入
一行，再读取第二页，OFFSET 就会把原第一页末行重复一次，并漏过一条尚未浏览的旧行。两类 Web 页面又会在
日志变更 SSE 后自动重读当前 offset 页，使这个问题在正常持续流量下可达，而不只存在于极端并发。

仅把第一页时间作为数据库快照不够：长流可以在较晚完成时插入一个较早的 `started_at_ms`。为此增加持久化
序号、服务端游标会话或跨 HTTP 请求持有 SQLite 事务，会引入 Schema、恢复、TTL 和内存上限问题；当前需求
只要求浏览时不因集合位移产生重复或漏行，不要求保存已经被 retention/容量策略删除的历史，也不要求构造
数据库级冻结快照。

随后确认的管理交互还要求直接跳转任意页。Web 顺序请求并缓存前面所有 Cursor 会把一次跳页放大成 N 次 HTTP/SQLite 查询；恢复完整行 `OFFSET` 又会重复读取被跳过行。分页协议因此需要在不放弃锚定遍历的前提下提供单次按页定位。

## 决策

- 两个管理列表使用 `page + page_size + cursor`：第一页首次读取不传 `cursor`，响应返回服务端收敛后的
  实际 `page`、当前页 `cursor`、可选 `next_cursor`、`page_size` 和锚定范围内的精确 `total`。
- Cursor 是不透明、版本化、按 RequestLog/HttpAccessLog 类型隔离的管理 API 值。它编码：
  1. 首次读取时最新可见行的 `(started_at_ms, request_id)` 头部锚点；
  2. Cursor 对应的页号；
  3. 后续页可选的上一页末行排他边界；
  4. RequestLog 当前规范化结构化筛选的固定长度指纹；HttpAccessLog 编码当前
     `show_admin_operations` 状态，关闭时管理 API 与管理 Web 静态资源属于同一筛选集合。
  Server 对长度、版本、类型、整数、Base64 文本和边界顺序做有界校验；格式错误返回既有
  `invalid_request`。RequestLog Cursor 的指纹与本次 query 不一致时同样拒绝，客户端不能借 Cursor
  改变筛选集合、日志保留谓词或查询其他数据。项目不保留旧 Cursor 版本兼容分支；Cursor 本来就只存在于
  当前页面内存，部署后自然重新读取第一页。
- Storage 继续按 `(started_at_ms DESC, request_id DESC)` 排序。所有锚定读取先约束行键不大于头部锚点，
  下一页再约束行键严格小于上一页末行；每次最多读取 `page_size + 1` 个摘要行，用额外一行判断是否生成
  `next_cursor`。现有时间/排序索引和 HttpAccessLog 摘要覆盖索引继续承担查询，不增加 Migration。
- 请求页号与 Cursor 页号相同且 Cursor 已带排他边界时直接走上述 Keyset 查询。两者不同时，Storage 在同一
  SQLite 读事务内先取得锚定精确总数并把页号收敛到合法范围，再用完全相同的窗口、锚点与筛选谓词执行由
  现有索引驱动且只选择 `(started_at_ms, request_id)` 的查询，以 `OFFSET ((page - 1) * page_size - 1) LIMIT 1`
  定位目标页前一行；随后仍以该行作为排他 Keyset 边界读取最多 `page_size + 1` 条摘要。禁止对完整日志列
  执行 OFFSET，也禁止 Web 为跳转第 N 页顺序请求前 N-1 页。
- RequestLog 的损坏行隔离语义不变。下一页边界从本页最后一个原始持久化排序键生成，再逐行执行领域解码；
  因此被跳过的损坏行仍计入 `total`，也不会让 Cursor 停在同一坏行反复读取。
- 这是一致的遍历边界，不宣称数据库冻结快照。首次读取之后，排序在头部锚点之前的新日志被排除；排序落在
  尚未遍历区间的迟到日志可以在后续页出现；已进入已遍历区间的迟到日志需要重新读取最新页才能看到。
  retention、容量淘汰和手动清理仍可删除 Cursor 范围内的行，Keyset 会从边界后第一个仍存在的行继续，
  不用 OFFSET 再跳过一行。
- Web 只保存当前 `page` 与一个当前 Cursor。相邻下一页使用响应的 `next_cursor`；上一页、首尾页和页码输入
  直接提交目标 `page` 与当前 Cursor，由服务端复用其头部锚点定位。首次页保持实时；一旦带 Cursor 浏览，
  即使返回第一页也保持同一锚点。修改每页条数、任一 RequestLog 筛选条件、清理成功或手动刷新都清除
  Cursor 并回到最新第一页。
- 已固定 Cursor 的历史页不再响应日志变更 SSE 自动重读，避免无变化查询和浏览视图漂移；第一页未固定时
  仍按现有开关响应事件。系统日志的自动刷新与“显示管理操作”偏好都按浏览器持久化，后者切换时清除
  Cursor 并回到最新页；Cursor 和页码都不持久化。
- `total` 每次仍按同一 SQLite 事务、当前 3 天窗口和头部锚点精确计算，因此 retention 或清理后可以收缩。
  Storage 把超出新总页数的请求收敛到最后一个合法页，响应必须返回实际页号；“下一页”是否可用只以
  服务端 `next_cursor` 为准。

## 后果

持续写入不会让已经浏览的 Keyset 页边界因集合位移而重复或漏过既有行；最旧行被删除时，下一页也从上次末行
之后的首个现存行继续。管理员可以用首尾页按钮或页码输入单次跳转任意页。随机定位的成本随目标页深度线性
增长，但边界查询只投影窄排序键，不读取被跳过的日志摘要/正文；默认 20 万行和最大 1000 万行仍由
已有日志容量设置约束，不为偶发管理查询建立持久化页索引或服务端 Cursor 会话。

Cursor 不进入 SQLite、浏览器持久化或运行态恢复，不形成新的会话管理、清理 Worker 或容量边界。代价是每个
标签页只在当前挂载期间保留返回路径；刷新页面会自然回到最新第一页，这与日志管理页的实时定位一致。
筛选指纹只绑定分页集合，不用于鉴权或防篡改；Server 仍必须独立解析并校验每个结构化筛选字段。

## 验证

- Storage 回归先读取第一页，再插入新的头部行和排序较早的迟到行，并使用返回 Cursor 读取后续页；断言既有
  行不重复、不因头部插入漏过，迟到且位于未遍历区间的行可见。
- Storage 回归在两页之间删除最旧行，断言 Keyset 从边界后的首个现存行继续；RequestLog 损坏行仍可跨过。
- Server/HTTP 契约覆盖两类 Cursor 类型隔离、畸形 Cursor 拒绝、响应 Cursor 链和 `total`。
- HttpAccessLog 契约覆盖管理活动开关进入 Cursor 作用域，关闭时管理 API 与管理 Web 静态资源在锚点、
  `COUNT`、随机页边界和页面数据中使用同一谓词。
- RequestLog Server/Storage 契约覆盖筛选后的列表与 `COUNT` 使用同一谓词、筛选指纹稳定，以及跨筛选复用
  Cursor 被拒绝。
- Web 契约与组件测试覆盖下一页复用精确 Keyset Cursor、页码输入直接提交目标页、历史页暂停 SSE、手动刷新/
  每页条数/清理重置到最新，以及总数收缩后的服务端页码收敛。
