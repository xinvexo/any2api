# ADR-0078: 有界并发与机会式分段发布 OAuth 定时刷新

- 状态：Accepted
- 日期：2026-07-31
- 修订：2026-08-04
- 决策者：maintainer

## 背景

OAuth 定时 Worker 过去对本轮全部到期账号使用无上限并发，并在每个账号刷新成功后分别取得配置发布锁、开启
SQLite 事务、重载完整配置、增加 revision、reconcile Runtime 并切换快照。账号数量增加时，这同时放大上游
连接洪峰和本地全量配置发布成本；后者还会让同一扫描批次产生许多对数据面没有独立价值的中间 revision。

账号刷新响应不能简单覆盖当前记录。网络请求期间可能发生管理员删除、同身份重新登录授权、导入或认证失败触发的另一轮
刷新，因此持久化边界仍必须逐账号执行 `token_version` CAS。

后续故障注入确认，等待整次扫描的所有网络 Future 后才发布会形成跨账号队头阻塞：一个 Token Endpoint 慢请求
会让已经成功的其他账号继续使用旧 Token，并让这些账号的 singleflight gate 一直保持到最慢请求结束。Token 响应
读取本身允许 30 秒，这一延迟远大于一次本地配置发布。账号之间不存在需要整次扫描原子切换的跨账号不变量。

## 决策

- 定时扫描最多并发执行 6 个上游 Token 刷新请求。该值是单节点资源保护常量，不新增 SettingRegistry 配置。
- 每个账号仍使用现有 singleflight gate；取得 gate 后重新读取账号与 Token 版本，不允许旧扫描结果覆盖新材料。
- 成功结果的 gate 持有到其所在分段发布结束。配置发布任务会脱离定时 Worker 的等待者继续完成，因此 gate 也
  必须转移到该脱离式任务；`Draining` 取消 Worker 不得在 SQLite 事务或快照切换仍在进行时提前打开同账号的
  第二条刷新路径；`Forced` 取消发布任务时则与事务回滚一起释放 gate。
- 网络请求各自独立成功或失败。Worker 持续轮询有界并发流，把当前已经完成、最多 6 项的 ready 结果合为一个
  机会式分段并立即发布；不得为了凑满分段或等待本次扫描的慢 Future 而扣留已成功账号。此处不增加固定毫秒
  聚合窗口；同时 ready 的结果仍会合并，错开的结果可以形成多个分段。单个网络或解析失败不阻断其他账号，也
  不进入 SQLite。
- 每个分段在现有配置发布锁内读取最新快照，并在一个 `BEGIN IMMEDIATE` 事务中逐项核对账号存在性和
  `token_version`。已删除或版本已变化的项视为过期结果并跳过；其他校验或数据库错误使整个事务失败。
- 每个分段至少有一个新鲜结果时只增加一次配置 revision，重载一次完整配置、reconcile 一次 Runtime，并
  切换一次 `PublishedSnapshot`；该分段全部结果均过期或输入为空时不提交、不增加 revision、不切换快照。
  数据面可以先看到快账号的新 Token，再看到后续慢账号；单个分段内部仍原子可见。
- Worker 记录本次扫描连续产生的全部分段 revision，并将其自身的连续通知消费后等待正常扫描间隔；若任意两个
  自有分段之间夹有外部配置提交，或扫描结束时已经出现高于最后自有分段的 revision，则立即重新扫描。Provider
  未返回新过期时间而继续保留旧的已过期安全边界时，不得因本轮自己的发布通知形成无等待热循环。
- 401/认证失败触发的按需刷新仍保持单账号 singleflight 和即时单账号 CAS 发布。它服务当前 Pending 请求，
  不等待定时 Worker 扫描或分段聚合。
- 交互式同身份重新登录在配置发布锁内使用当前 `token_version` 做重新授权 CAS；成功后旧定时/按需刷新结果因版本变化自然过期，不得覆盖新登录材料。完整身份匹配和本地配置保留语义见 ADR-0087。
- `enabled=false` 账号继续参与定时认证保活；分段刷新不得改变启用状态、已选模型、RPM 或管理元数据。

## 备选方案

- 等待整次扫描完成后只发布一次：配置成本最低，但故障注入证明任一慢账号可以把其他账号的 Token 可见性和 gate
  拖到自身网络超时，跨账号原子快照没有对应产品不变量，收益不足以抵消在线阻塞。
- 每个账号完成后强制单独发布：消除队头阻塞，但即使 6 个响应同一轮 poll 已经 ready 也会制造 6 次 SQLite
  事务、全量编译、Runtime reconcile 和 revision。机会式 ready 分段保留同轮合并而不等待慢账号。
- 首个完成项后等待固定毫秒窗口：可以提高分段命中率，但会人为增加每个刷新延迟并引入新的时钟常量；当前
  ready-set 语义已经提供确定、无额外 timer 的有界折中。

## 后果

- 定时刷新网络并发和连接占用不再随账号数无界增长。
- 同一次 poll 已经 ready 的最多 6 个结果只发布一次；响应同时完成时显著少于逐账号发布，响应错开时允许最多
  每个成功账号一个 revision，以换取快账号不等待慢账号。数据面只要求每个账号的 Token CAS 和每个分段原子，
  不再承诺整次扫描的跨账号原子快照。
- 缺少新过期时间的成功刷新最多按配置的扫描间隔再次尝试，不会占满 CPU、上游连接或配置 revision。
- 网络阶段与发布阶段之间允许账号变化；Token Version CAS 使这些竞争以逐账号跳过收敛，不需要长时间持有发布
  锁或数据库事务覆盖外部网络 I/O。

## 验证

- 测试记录同时进行的 Token 请求峰值，证明不超过 6。
- 同时 ready 的成功结果只增加一个 revision；分两次 ready 的结果形成两个 revision，第一段在慢请求完成前可见
  且其账号 gate 已释放。
- 同段一个过期或已删除结果不会阻断其他新鲜结果；全部过期不增加 revision。
- 单个网络/解析失败不取消其他成功账号；按需认证失败刷新仍立即发布。
- 多个连续自有分段以及缺少新过期时间的刷新不会因自身 revision 连续立即重扫；分段之间或扫描结束后的外部
  revision 仍会触发立即重扫。
