# ADR-0039: 总览承载运行态聚合，设置采用渐进披露

- 状态：Accepted
- 日期：2026-07-25
- 决策者：maintainer
- 调整：ADR-0012 的 Web 管理面、ADR-0038 的 Web 展示位置

## 背景

负载均衡和会话粘性本质上是路由策略，却各自占用一个一级导航和独立页面；同时它们又把相同的
`scheduler.*`、`affinity.*` 设置嵌入页面，系统设置中仍存在另一份入口。随着 SettingRegistry 增长到
数十项，按内部模块平铺页签与表单会让个人自托管用户面对大量低频参数，常用操作反而难以找到。

运行态聚合回答的是“实例现在怎样”，更适合总览；配置回答的是“实例以后怎样运行”，应集中在设置。
两者不能继续混在独立功能页中。

## 决策

- 一级导航删除“负载均衡”和“会话粘性”。旧 `/balancing`、`/affinity` deep link 重定向到
  `/settings/routing`，不保留双轨页面。
- 总览展示固定规模的服务、全局/Provider 调度、队列和会话绑定聚合。它不展示账号 ID、Credential
  分布、模型健康、Session Hash 或绑定样本。
- `GET /api/admin/balancing` 继续使用 ADR-0038 的 aggregate-only 契约。
- 总览读取 affinity 时使用 `limit=0`；Runtime 将该值解释为 aggregate-only，不构造逐 Credential
  计数或绑定样本，响应数组为空，因此账号或绑定数量增长不会扩大浏览器响应。
- 系统设置固定为四个一级页签：
  - 基础：管理员密码与远程管理；
  - 路由策略：`scheduler.*` 与 `affinity.*`；
  - 运行保护：重试、冷却、熔断、上游网络、OAuth 刷新、流式边界与停机；
  - 日志：请求日志与本地文件日志。
- 每个页签默认只直接展示高频设置，低频设置进入同页“高级设置”折叠区。折叠只是渐进披露，所有
  SettingRegistry 项仍可编辑、校验、恢复默认并遵守同一 revision 发布边界。
- 全局代理只在出口代理页配置；设置页删除重复入口。

## 高频设置

- 基础：远程管理开关；
- 路由策略：RPM 用尽行为、软粘性开关、软粘性模式；
- 运行保护：最大总尝试次数、上游读取超时、严格 SSRF；
- 日志：请求日志开关、文件日志级别。

其余设置保持可用但默认折叠。新增设置必须明确归入高频或高级集合，禁止重新按内部模块增加一级
页签。

## 后果

管理导航减少两个一级入口，设置页从七个页签收敛到四个。总览只包含固定数量的聚合块；即使存在
1000 个账号或大量会话绑定，也不会构造或传输逐账号目录。高级用户仍能访问全部设置，但普通用户
首次进入时只看到最常用的少量决策。

## 验证

- 路由与导航测试确认旧 deep link 重定向且侧栏不再出现两个独立入口；
- 总览测试覆盖服务、调度、Provider 与 affinity aggregate-only 数据；
- Runtime 测试确认 affinity `limit=0` 不构造 Credential 计数或绑定样本；
- 设置测试确认四个分类、常用项直接展示、高级项默认折叠且展开后仍能保存和恢复默认；
- E2E 覆盖 `/settings` deep link、总览与 390px 导航无水平溢出。
